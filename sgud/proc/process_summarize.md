# 處理要點 — 摘要(summarize)之開發與驗收、設定、維運與監看

> 本檔屬本套件之處理要點分檔(摘要之開發與驗收流程、設定、維運與監看);路徑相對於 `src/`,測試在 `test/`。套件結構、發布面與編譯見 `process.md`;現況見 `../state/state.md`;規則見 `../rule/rulebook_summarize.md`(SUM-01～13)。

## 本套件之開發與驗收

- **定位**:通用知識摘要之管線(預篩 triage → 摘要 summarize → 分類法重標 retag → 內容同步 sync)。除抓取套件外不 import 其他專案程式碼(GEN-11),維持通用套件角度、不預設特定領域;設定與提示詞有預設、可由外部覆寫;內含完整測試、檢定標準與免費 AI 能力評分。
- **邊界**:只經 `src/core/capturePackage.mjs` 取抓取之件(名單明列,新增名稱須經套件維護者,每一名須有非測試取用),測試另有唯一之 `test/tools/captureForTest.mjs`;本套件 `src/core/` 與抓取套件之 `src/core/` 無同相對路徑之檔;抓取缺能力者於抓取套件以 opt-in 擴充(預設不變、附測試),不在本套件另寫。結構測試 `unit-summarize-package` ①。
- **共用件之家**(GEN-19):待判登錄之件(holdKey、putHold、resolveHold、listHolds、requestRetry、存量待判件等)、存量處置帳之協定(stockLedger)、掃描之累計器、功能表之檢核機制(`featureProblemsOf`)、提示詞覆寫之驗證、詞彙表解析(vocabKit)、值工具、核心件之日誌字樣皆在抓取套件,本套件只經抓取埠取用;判定小組之組成與必填(`core/standards/panelConfig`)、未成立原因之字樣表(`core/standards/panel.mjs` 之 `PANEL_WHY_LABELS`)、單頁執行器(`core/standards/panelRun.mjs` 之 `runPanelPage`)、批次 AI 之字樣(`core/stages/aiBatchStage.mjs`)在本套件;筆記待判之期限為 `noteHoldDeadlineOf`(`stores/noteHolds`)。
- **守門**:舊名、沿革與面向使用者字樣之判準一份(抓取套件之 `test/tools/historyMarks.mjs`,經 `test/tools/captureForTest.mjs`;`unit-summarize-package` ④ 掃 README、`package.json` 與 `src/`);本套件之具名例外只一項——提示詞原文「跨篇關聯與提煉」(`src/domain/noteDomain.mjs`),改即改提示詞(SUM-07 標準檔須重產、既有評比列之提示詞指紋失效)。
- **測試**:自套件根 `npm test`(＝`mocha --parallel "test/*.test.mjs" --timeout 180000`);單檔去掉 `--parallel` 換檔名;不連網、不呼叫真 AI;真 AI 之案(`api-summarize-bench-ai`)以 `WK_LIVE_AI=1` 才跑(燒免費額度,須使用者同意)。改本套件者另跑下游套件與使用端之全套(使用端之編排層經本套件跑摘要);改抓取套件者另跑本套件及其下游與使用端。
- **免費 AI 能力評分**:`node src/bench/cli.mjs --role all --models free --runs 2 --out <專案外目錄> --env <金鑰檔> --board 模型評比.csv`(五角色 × 免費模型 × 2 回;README §13 載每模型每回 26 次呼叫、8 個免費模型)。**`--out` 必放專案外**(AI 工作目錄＝`<out>/ai-workspace`;在專案下 CLI 型模型會讀本專案之指示檔〔如 `CLAUDE.md`〕,量到的不是通用能力)。長跑以 detached 執行。opencode 免費池有每日額度(UTC 0 時重置),一天約只夠一次全量;撞額度之模型停測、該角色不寫評比表,隔日 `--role <角色> --models <id>` 補。單一模型某角色 0 分而「呼叫失敗 1」者是整頁呼叫失敗,不是判斷錯——補跑該格即可。使用自己的題組與詞彙時(`--cases`〔SS5／SS14／SS9 檢定標準題組可直接用〕、`--vocab`〔最高證據等級之要件與忠實性之領域句一併填回〕)**不給 `--board`**(會覆蓋同角色同模型之通用題組列)。(命令列用法字串與題組路徑:`bench/summarizeBench.mjs` 各角色之 `command`、`casesHelp` 與 `bench/cli.mjs` 之用法／錯誤訊息,以及 `--help` 首行〔抓取套件 1.0.2 起〕皆為 `node src/bench/cli.mjs`／`src/bench/cases/…`,`unit-summarize-bench` 以實際直接執行 `--help` 與失敗路徑守之。)

## 摘要(summarize)之設定、維運與監看

- **子階段順序**:triage(預篩:標題＋開頭片段;長文另附中段)→ summarize(依字數打包:每批 ≤ `summarize.docsPerCall`×`summarize.charsPerDoc`＝18,000 字、≤3 篇;上限內長文全文進 AI)→ retag(分類法同步;有工作且扣掉保留時間〔使用端以 `stageOpts.retag.reserveMs` 或每輪依賴 `deps.reserveMs` 注入〕後剩 5 分才處理,每次呼叫預算亦扣保留)→ sync(筆記內容變更之偵測,無 AI)。
- **保留時間(預篩、摘要、重標三段同一份,SUM-14)**:同一輪後段另有耗時之工作者,由組裝者以每輪依賴 `deps.reserveMs` 給一次(或 `stageOpts.<triage|summarize|retag>.reserveMs`;`opt` 明給者優先,含 0)。保留 > 0 時預篩與摘要於開工前、每輪開工前須「扣保留後剩餘 ≥ 該席位一次呼叫之估計」(鏈首家之單次逾時:席位 `timeoutMs` → `ai.providerTimeouts[use]` → `ai.extraProviders` 該條目自帶 `timeoutMs` → `ai.timeoutMs` → 300000),不足則少做幾輪（`rounds`／`docsPerCall` 不縮）、文件留池待下輪，report `detail.deferred:true` 且日誌寫明；每次呼叫以「剩餘−保留」封頂。**巡檢判讀**：`stopped` 而無 `deferred` ＝ 整輪預算本身用盡或容量用盡；有 `deferred` ＝ 因保留而讓出時間（調整組裝者之保留或降容量，不是本套件缺陷）；修補／覆核於時間不足時本批不套用、不記次、文件下輪重摘。保留未給 → 行為不變。
- **素材問題回報**:預篩／摘要判非知識而理由直指素材壞了(亂碼、未載入、只抓到導覽…;不含付費牆／登入)→ 不丟,退回抓取之瀏覽器佇列並排除產生該素材之方法(curl 來源 → 不用 curl),同一篇至多一次(`summarize.refetch.max` 1;0＝停用)。安裝方追加樣式填 `summarize.refetch.patterns`([{p,f}])。內建樣式(`stores/materialPolicy` 之 `MATERIAL_PROBLEM_PATTERNS_DEFAULT`)保守——須直指素材本身、不收題材判斷,存取限制另有排除樣式(`MATERIAL_EXCLUDE_PATTERNS_DEFAULT`);改樣式後須以真實 skip 理由比對命中與誤收。
- **分類法變更(要點 4、5)一律改詞彙表(`cfg.data.vocab`)**:新增類別 → 加進 `categories`(可另給 `categoryHints: { 類別: [關鍵詞] }` 擴大重判範圍);改名 → 新名加進 `categories`、舊名移出、`categoryRenames: { 舊: 新 }`(連續改名保留舊對照即可);退役 → 移出 `categories` 並列 `categoryRetire`;內容類型／證據等級改名 → `claimTypeRenames`／`evidenceLevelRenames`(下游若有以該名為鍵之設定須另行同步,本套件不驗)。**移除而不宣告去向** → 每輪 WARN「分類法守門」(須見)、資料不動。下一輪 retag 自動排工作:改名機械(不呼叫 AI)、新增／退役 AI 重判(席位 `summarize.retag.ai`;預設每輪至多重判 `retag.perRun`＝60 篇、每批 `notesPerCall`＝20 篇,約 3 次呼叫,逾量者分輪完成)。guide 措辭改了而清單未變 → 以 `requeueCategory` 明示排入該類別之重判。
- **維運 API**(皆具名匯出,寫入者由呼叫端取整輪執行鎖):`ops/taxonomyOps` 之 `taxonomyStatus`(唯讀:版本、下一輪將排入之工作與守門、待處理篇數、預估呼叫)／`requeueCategory`(排入重判)／`categoryProposals`〔`proposalsOf`〕(模型給之清單外類別＝筆記 `categoryRaw`,依篇數排;採納＝加進 `categories`,`categoryRaw` 恰為該類者機械改、零 AI);人工筆記匯入 `ingestNotes`(與摘要同一組裝)。狀態檔 `state/taxonomy.json` 為真理檔:無法解析時 retag 停止並 WARN「分類法守門」,刪除＝以現行分類法為已套用(未完工作作廢)。分類法狀態之唯讀快照(版本、待處理工作數、守門數、md 待修補數)取 `taxonomySnapshotOf(stateDir)`。
- **監看**(日誌;字樣契約在 `logContract.mjs` 之 `SUMMARIZE_LOG_KNOWN`〔已知常態 WARN〕、`SUMMARIZE_LOG_MUST_SEE`〔一律須見〕、`SUMMARIZE_LOG_PARSE`〔逐輪數字正則〕,以 `unit-summarize-log-contract`、`unit-flow-summarize` 對實際日誌驗證):一律須見者——`逐項鏈異常`、`分類法守門`、`篇筆記之 md 讀不到`、`皆無預篩結果`(另含批次 AI 機制與核心件所發之須見字樣)。常見字樣:`預篩：素材問題退回抓取[…]`／`摘要：素材問題退回抓取[…]`、`摘要分類[…]：「X」不在分類清單，落「<fallbackCategory>」（原值存 categoryRaw）`、`分類法：首次記錄／排入重標工作——…／重標工作完成——…／本輪重標 N 篇`、WARN `分類法守門：…`(須見)、WARN `分類法：筆記 … md 改寫失敗`／`重判 2 次未成`;摘要段 summary 尾「｜素材退回 N｜長文截斷 N｜重標 N 篇（AI N 次）｜內容變更 N 篇」。
- **內容變更(sync 子階段,無 AI)**:使用者手改筆記 md 之標題(frontmatter `title`)、概念(`concepts`)或「一句話重點」章 → 下一輪自動偵測(只讀 mtime 新於上次掃描者),同步回記錄並寫 `knowledgeChangedAt`,供下游據以重判。改其他章(核心知識等)或分類欄位不觸發。要立刻同步:呼叫 `syncNotes(deps, { ids: [slug] })`(或 `{ all: true }` 全量;寫入者由呼叫端取執行鎖)。**同步入口過筆記標準**(2026-10-05 起):可確定性修正者(簡體、[object Object] 行、概念計數尾碼…)寫回 md;仍不合格者登錄待判(使用者;以抓取套件之 `listHolds` 列出),同步照做。
- **摘要失敗之重開**(2026-10-05 起):`summarize-failed`(逾次未納入)之文件,使用者修正後以 `reviveFailedDocs(stores, { match, nowIso, apply })` 重開(預設只預演;`apply:true` 才寫:原文自 docTexts 回填、狀態回 raw、tries 歸零,下輪重摘;寫入者由呼叫端取執行鎖),或以 `waiveHold`(抓取套件)確認不納入;無原文者列於回傳之 `noText`、不重開,須重抓。
